# AskTube — Full End-to-End Feature Verification
Perform a comprehensive verification of **everything implemented in AskTube so far**.

This is a TEST/VERIFICATION task.

## CRITICAL RULE
Do NOT implement new product features.

Do NOT refactor working code.

Do NOT change architecture.

Do NOT modify production behavior merely to make tests pass.

Only make a code change if you discover a genuine defect required to fix the existing implementation. If you find a defect, document it clearly before/after the fix.

The goal is to determine whether the current AskTube pipeline actually works from ingestion through grounded answer generation.

# 12. Grounding Verification
Perform an explicit hallucination test.

Use a context that says:

```
"React was created by Facebook."
```
Ask something unrelated that is NOT present in the context.

For example:

```
"What year was React created?"
```
The system should NOT confidently invent an answer from outside knowledge.

Expected behavior:

```
Insufficient information in the provided transcript context.
```
The exact wording may differ.

The important behavior is that unsupported information is not fabricated.
