# AskTube

## Implementation Summary

AskTube is a YouTube playlist analysis application whose current implementation includes robust local playlist URL validation, YouTube Data API v3 retrieval, and PostgreSQL persistence for playlist and video metadata. The backend keeps the existing API contract intact while persisting the discovered metadata in a durable SQL database before returning the playlist payload to the frontend.

## Database Schema

Playlist entity
- playlist_id: unique natural key from the YouTube playlist ID
- title
- description
- thumbnail
- channel_id
- channel_title
- published_at
- created_at
- updated_at

Video entity
- id: internal numeric primary key
- video_id
- playlist_id (foreign key to playlists.playlist_id)
- title
- description
- thumbnail
- position
- published_at
- video_url
- duration
- available
- created_at
- updated_at

Relationship
- One playlist has many videos.
- Each video is uniquely constrained by (playlist_id, video_id) to prevent duplicates.
- Position is preserved and used for ordered retrieval; videos are not alphabetized or date-sorted.

## Known Issues

- FastAPI dependency/environment issue: if the backend environment is not created or requirements are not installed, the app will not run correctly until `python -m pip install -r requirements.txt` is executed.
- Windows `.next/trace` permission lock: stale Next.js trace files can still block a clean build on some Windows machines. This remains a known local issue and must be cleared before a clean production build is expected to complete.
- PostgreSQL runtime configuration must be present for real database persistence; no credentials are committed or exposed.
